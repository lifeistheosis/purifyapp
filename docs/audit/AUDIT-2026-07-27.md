# Purify audit plan

## 1. The headline

Purify is a genuinely large, well-architected app whose website is healthy and whose Android build is quietly broken in the ways that matter most: the app opens on a frozen date, its prayer sync never reaches the server, and a quarter of its download is duplicated navigation data. Every automated guardrail the owner believes is running is off, because CI has been aborting at the Lint step since roughly 2026-07-13, so typecheck, unit tests, the production build, axe and Lighthouse have not run on any push in two weeks. **The single biggest thing to fix is that the Android app's daily surfaces are baked at build time**: verified in the current export, `out/prayers/index.html` contains the literal "July 27, 2026" and `out/index.html` bakes `Panteleimon`, so from day two after a release every user sees the wrong saint, the wrong fast, the wrong readings and the wrong Pascha countdown until they install a new APK.

Three findings from the auditors are already fixed and need no work: all four version identifiers were bumped to Beta 2.6 in `74dfd83d` (verified: `lib/whatsNew/version.ts:6`, `public/sw.js:22`, `android/app/build.gradle:18`, `data/changelog/patches.json`), the goalpost tab glyph was replaced with `OrthodoxCross` (`components/nav/MobileTabBar.tsx:20,112`), and `NEXT_PUBLIC_COMMUNITY_ENABLED: "1"` is now hardcoded in `.github/workflows/android-apk.yml:95`.

## 2. Do these first

Ordered by user impact per hour of work.

### 2.1 Unfreeze the day in the Android app
**What.** Every daily surface computes the date in a server component under `output: "export"`, so it runs once at build time. `components/today/TodayMobileV3.tsx:51`, `components/mobile/DiscoverMobile.tsx:54`, `components/mobile/PrayersMobile.tsx:59`, `app/(app)/prayers/today/page.tsx:50`, `app/(app)/calendar/page.tsx:199` all call `startOfDayUtc(new Date())`. `export const revalidate = 3600` is a no-op in a static export. Verified in `out/`: `grep -c "July 27, 2026" out/prayers/index.html` returns 1 and `out/index.html` contains `Panteleimon`.
**Why it matters.** This is the entire reason a person opens an Orthodox app in the morning. It also makes `/fasting` (which is correct) contradict the Home tab on the same device.
**Fix.** Move the day computation to the client on those four surfaces. The working pattern already ships: `components/fasting/FastingTrackerClient.tsx:79` does `useMemo(() => new Date(), [])` and calls the same fs-free pure helpers (`commemorationsOn`, `fastingStatus`, `readingsOn`, `paschaInfo` in `lib/calendar/orthodox.ts`), which are already imported into client components in `CalendarCell.tsx`, `FastBadge.tsx` and `TrapezaClient.tsx`. Keep the server shell for `metadata` and first paint. Fix the timezone bug in the same edit (2.2). Add a unit test asserting no daily surface renders a hardcoded date.
**Effort.** Medium to large. Not owner-gated.

### 2.2 Use the reader's day, not UTC
**What.** `lib/calendar/orthodox.ts:57` `startOfDayUtc` returns the UTC calendar day. `lib/fasting/streak.ts:49-57` documents this exact trap and exports `localDayToUtcNoon`, used in exactly one place (`components/fasting/FastingTrackerClient.tsx:11`). Every other consumer takes the UTC day, including `components/trapeza/TrapezaClient.tsx:35`, which is a client component and therefore wrong on the device too.
**Why it matters.** Every US reader from roughly 7pm local until midnight sees the next day's saint and the next day's fasting rule. On 13 August the Today card says Dormition while `/fasting` says the Dormition fast, in the same app, the same evening. Telling someone a fast is over a day early is a real harm for a fasting app.
**Fix.** Swap `startOfDayUtc(new Date())` for `localDayToUtcNoon(new Date())` at every call site, resolved on the client. `TrapezaClient.tsx:35` is a one-line fix on its own.
**Effort.** Small once 2.1 lands. Not owner-gated.

### 2.3 Stop stamping "Verified buyer" on seeded reviews
**What.** `app/api/shop/catalog/reviews/route.ts:40` does not select `order_id`, and `components/shop/ReviewsSection.tsx:103` renders `<VerifiedBuyerBadge />` on every row unconditionally. `app/api/admin/shop/reviews/route.ts:170` inserts directly with `order_id: null`, bypassing the delivered-order gate in `shop_submit_review`. Live probe confirms a 5-star review is served on `greek-33-knot-prayer-rope` today. `VerifiedBuyerBadge.tsx` documents the badge as "always truthful" because the submit RPCs require a delivered order, which is false for the seed path.
**Why it matters.** A shopper sees a testimonial for a purchase that never happened. This is the fabricated-review practice the owner previously declined, shipped by a different route, and it is live FTC exposure under 16 CFR Part 465.
**Fix.** Three parts. (a) Add `order_id` to the select in `app/api/shop/catalog/reviews/route.ts:40` and the store-reviews route, and gate the badge on `r.order_id !== null` in `ReviewsSection.tsx:103` and `StoreReviewsSection.tsx:106`. (b) Owner deletes the seed rows (SQL in section 4). (c) Add `.not("order_id","is",null)` to `fetchRows` so a seed can never reach the storefront again.
**Effort.** Small. Step (b) is owner-gated.

### 2.4 Close the fail-open cron auth
**What.** `app/api/cron/push-deliver/route.ts:32` and `app/api/cron/bmc-snapshot/route.ts:16` both read `const secret = process.env.CRON_SECRET` then `if (secret) { ...403... }`. When unset, the guard is skipped entirely. Live probe: `/api/cron/bmc-snapshot` returns 503 and `/api/cron/push-deliver` returns 500 to an unauthenticated caller, never 403, which proves the secret is unset and both handlers executed.
**Why it matters.** Both run under the service role. `bmc-snapshot` upserts `donations_monthly` on demand from any anonymous request. `push-deliver` is inert only because its tables do not exist; the moment the push migration lands, any anonymous GET fans out reminders to every device with no rate limit.
**Fix.** Invert the condition in both files: `if (!secret) return NextResponse.json({error:"Not configured."},{status:503});`. Two lines each. Same degrade-closed shape as `lib/shop/flags.ts:19-23`.
**Effort.** Small. Setting `CRON_SECRET` on Render is owner-gated.

### 2.5 Get CI green
**What.** `npm run lint` at HEAD prints `13 problems (6 errors, 7 warnings)` and exits 1 (reproduced). `.github/workflows/ci.yml` has one sequential job, so Lint failing means Typecheck, Unit tests, Build, Playwright smoke, axe and Lighthouse never run. Dating: `git show 513fb0d4:lib/fasting/tracker.ts` (2026-07-13) still fails under the current config, and the eslint config last changed 2026-07-19.
**Why it matters.** A type error, a broken test, a failed production build or a new WCAG violation can be merged and deployed with nothing going red. The AGENTS.md release ritual is being enforced by hand only.
**Fix.** Three real edits: (1) `lib/fasting/tracker.ts:121`, hoist `const todayKey = dayKey(today)` above the memo and use `[statusByDay, kindOf, todayKey]`, which also retires the stale disable on line 120; (2) `components/shop/CategoryClient.tsx`, move the `set-state-in-effect` disable from line 36 to line 40 where the rule actually reports; (3) `components/gifts/GiftBox.tsx:107`, wrap `giftPresentation(gift.tier, gift.days)` in `useMemo` keyed on `[gift.tier, gift.days]`, killing all four `preserve-manual-memoization` errors. Then split the job so Lint, Typecheck, Unit, Build and E2E are independent and a lint nit can never hide a broken build again.
**Effort.** Small. Not owner-gated.

### 2.6 Fix the tab bar overflow in non-English locales
**What.** `components/nav/MobileTabBar.tsx:173` is `<li key={key} className="flex-1">` with no `min-w-0`, and the label span (line 210, verified still `<span className="leading-none">{label}</span>`) has no truncation, so min-content width wins over the 1/7 flex share. The container is `overflow-visible`, so nothing clips or scrolls. Measured at 360px: el `ul` scrollWidth 399, last tab right edge 421; fr 376/398; ru 361/383; ro 354/376. The seventh tab (You) ends 16 to 61px past the screen edge.
**Why it matters.** A Greek, French, Russian or Romanian user in the Android app cannot reach account, sign in, sign out, notifications, Diptychs, Premium or Support at all. Those are core Orthodox audiences and Beta 2.3 shipped 21 selectable locales.
**Fix.** Add `min-w-0` to the `<li>` and `truncate max-w-full` to the label span. Two classes. Verified in-page that this drops Greek from scrollWidth 387 to 316 and equalises all seven cells at 41.4px.
**Effort.** Small. Not owner-gated.

### 2.7 Sweep the raw relative `/api/` fetches out of native code
**What.** AGENTS.md:26-30 is explicit that native pages must use `apiFetch` because the shell is served from `https://localhost`. Confirmed non-admin offenders: `lib/prayers/sync.ts:57,74` (`/api/prayer/sync`), `components/onboarding/OnboardingFlow.tsx:269` and `components/auth/SignUpForm.tsx:50` (`/api/legal/accept`), `components/analytics/AnalyticsTracker.tsx:42,55` (`/api/track`), `components/saints/BumpButton.tsx:172`, `components/shop/SaintIconsRail.tsx:34`. All ship in the bundle. All swallow their failures.
**Why it matters.** Prayer completions, living and departed intentions and rope sessions never reach the server, and never come back on another device. With Android Auto Backup disabled (`docs/launch/ANDROID-LAUNCH-CHECKLIST.md:140`), a reinstall permanently loses the names a user prays for, which is the most personal data in the app, and cross-device sync is a paid Plus benefit. The clickwrap legal-acceptance record is never written for anyone who signs up inside the app, which is a hole in the ToS hardening exactly where the mobile users are. All native analytics are lost, so the `/admin` numbers describe the website only.
**Fix.** Swap each to `apiFetch` from `@/lib/api/client`. Server side, `app/api/prayer/sync/route.ts:51,109` uses cookie-bound `createClient()` and exports no `OPTIONS`, so also swap to `createClientFromRequest(req)`, wrap in `corsRoute`, and `export const OPTIONS = corsPreflight`. Same for `/api/legal/accept`, `/api/saints/[slug]/bump`, `/api/shop/products`; `/api/track` is anonymous and only needs CORS. This is the remedy already applied under F-21 to `lib/push/native.ts`. Then add a grep gate in `scripts/android-build.mjs` that fails on `fetch("/api/` outside `components/admin` and the stashed trees, so this cannot come back a fourth time.
**Effort.** Small to medium. Not owner-gated.

### 2.8 Stop baking the search corpus into every page
**What.** `app/(app)/layout.tsx:55` mounts `CommandPaletteMount`, a server component (`components/search/CommandPaletteMount.tsx:10-11`) that awaits `buildSearchCorpus()` and passes the whole list as a prop. Under `output: "export"` that is baked into every route's RSC payload and again into every `index.html`. Measured: present in 3,504 exported files, 188,958,456 bytes raw. Stripping it: raw 522.3 to 341.2 MB, deflated 109.9 to 74.0 MB, saving 35.9 MB of compressed download. `out/about/index.html` is 125,256 bytes of which 57,057 is the corpus.
**Why it matters.** 21% of everything a user downloads and stores is 3,504 identical copies of the same navigation list, and every soft navigation fetches another 50 KB copy. It also costs WebView parse time on every hard load.
**Fix.** Make the mount a client component and have `components/search/CommandPalette.tsx` lazily `fetch('/search-corpus.json')` on first open. That exact shape already works offline inside the shell: `lib/content/bootstrap.ts:98` does `fetch('/content/content-package.json')`. Emit the file post-export in `scripts/android-build.mjs` next to the existing `build-content-package.mjs` step, reusing `buildSearchCorpus()` so there is one source of truth. Keep the same fetch on web.
**Effort.** Medium. Not owner-gated. Biggest single size win in the app.

### 2.9 Stop shipping and importing the dead content package
**What.** `out/content/content-package.json` is 37.6 MB raw / 12.1 MB deflated, 911 records, of which `saint_writing` is 32.5 MB. It is fetched, parsed, SHA-256 verified and inserted twice (content + search_index) on every native cold start via `components/content/ContentProvider.tsx:32` to `lib/content/bootstrap.ts:98` to `lib/content/manifest.ts:143-160`, one `tx.run` at a time across the SQLite JS-to-Java bridge. Nothing reads it: `grep -rn "useRepository|useLocalContent|useSyncQueue" app components lib` excluding the provider and tests returns zero.
**Why it matters.** Every user pays 12.1 MB of download and roughly 40 MB of on-device database for a store no screen queries, plus a parse and hash of ~37 MB and 1,822 bridge round-trips at the very first app open. On a mid-range phone that is a multi-second freeze or an OOM kill at the worst possible moment.
**Fix.** Gate the bootstrap behind an env flag defaulting off, the way `NEXT_PUBLIC_CAMPAIGNS_ENABLED` gates campaigns, and stop emitting `out/content` in `scripts/android-build.mjs` until a screen reads through `useRepository()`. Do not delete `lib/content/*` or `content-package.json`; the SQLite reader migration is the long-term size answer. If the package must stay, at minimum pass `{ verify: false }` on device (`scripts/verify-package.mjs` already verifies at build time, `android-build.mjs:276`) and drop the `search` field, which `scripts/build-content-package.mjs:209` already excludes from the checksum and which alone halves the file.
**Effort.** Small. Not owner-gated.

### 2.10 Give the daily rule a bell that actually rings
**What.** Onboarding step 3 requests notification permission and reports success (`components/onboarding/OnboardingFlow.tsx:78-94,195-205`), and `components/profile/PushOptIn.tsx` offers a toggle. Both route through `lib/push/reminders.ts`, which is server push only. Server push is entirely inert. `package.json` has `@capacitor/push-notifications` but no `@capacitor/local-notifications`, and `LocalNotifications` appears nowhere in the repo.
**Why it matters.** Every new user is asked for a notification permission on first run, told it worked, and never reminded of anything. Android will not re-prompt once denied, so the permission is being burned. A prayer app built on a daily rule has no way to say "it is evening", which is the one retention mechanic it is missing and the only one the anti-streak ethos permits.
**Fix.** Add `@capacitor/local-notifications` and back `lib/push/native.ts` with it: two repeating local notifications at the `MORNING_DEFAULT` / `EVENING_DEFAULT` times already defined in `lib/push/client.ts`. No server, no FCM key, no cron, works with no signal, fires at the user's own local time. Keep the existing reminders facade so `OnboardingFlow` and `PushOptIn` need no changes.
**Effort.** Medium. Not owner-gated.

### 2.14 Make sync capable of deleting
**What.** `grep -rn '\.delete()' lib/sync/*.ts` returns nothing. `lib/sync/bookmarks.ts` only upserts (line 105) and then merges every server row back into localStorage (:116-186). Same shape in `annotations.ts:112,129` and `florilegium.ts:101,125`. `app/api/prayer/sync/route.ts` is upsert-only at lines 127, 153, 158.

### 2.15 Recalibrate the size guard before it lets a rejectable build through
**What.** `scripts/android-build.mjs:218` sets `OUT_SIZE_BUDGET_BYTES = 0.9 * 1024**3` and sums **raw** bytes excluding `_next`, then only `console.warn`s. Current export is 625.8 MB raw, so it prints "no i18n leaks" and stays silent. But the measured deflate ratio for this content mix is 0.273, so 0.9 GB delivers at roughly 245 MB and Play rejects at 200 MB.
**Why it matters.** The assets alone already deflate to 170.8 MB against a 200 MB ceiling, before dex, resources and the per-ABI native libs from Capacitor SQLite, RevenueCat, Firebase and social login. Real headroom is well under 30 MB, and the workflow comment in `android-apk.yml` records that the baked patristic commentary added ~25 MB in Beta 1.9.1. **Fix.** In the same function, accumulate `zlib.deflateRawSync(buf, {level:6}).length` per file, this time including `_next`, compare against a compressed budget of ~150 MB, and `process.exit(1)` on overrun the way the i18n leak branch already does at line 247. Print both numbers each build. Record today's baseline in the message: 625.8 MB raw / 170.8 MB deflated. Land 2.8 and 2.9 first; together they take the asset payload to roughly 123 MB.
**Not verified.** No AAB or APK exists locally, so 170.8 MB is a measured floor for assets, not a measured bundle. The next CI run should record the actual `app-release.aab` byte count as the true baseline.
**Effort.** Small. The AAB measurement is owner-gated.

## 3. The big rocks

Larger efforts worth committing to, roughly in order of return.

**Saint of the day coverage.** Probed against `commemorationsOn` and `getSaint` using the exact resolution logic in `TodayMobileV3.tsx:58-61`: over 365 days of 2026, 60 days resolve to a profiled saint and **305 fall back** to a name, a ✦ placeholder and an "Open in calendar" link. Misses include Theophany, the Synaxis of the Forerunner, the Circumcision and St Sava. The corpus is 108 linked profiles; Athon leads with 1,093. Five days out of six, the daily hook dead-ends. Cheap half-step first: link the fallback to `/calendar?d=YYYY-MM-DD` instead of the bare grid and let `TodaySaintCard` render the commemoration note as body copy. The real fix is writing profiles for the ~120 days carrying a named feast or great-martyr, ordered by frequency in `commemorationsOn`. Owner-gated: hagiography is editorial content under `docs/editorial-standards.md` and goes through the clergy queue.

**Light mode.** `SUGGESTIONS_AUDIT.md:34-37` records a public commitment dated 2026-07-25 to app-wide light mode, explicitly not behind Pro, asked for because elderly readers report dizziness on the dark palette. A repo-wide grep for `prefers-color-scheme`, `data-theme`, `themeToggle` or `lightMode` across `app/`, `components/` and `lib/` returns nothing. The Pro Parchment mode recolors only the reading surface, so the chrome stays dark. The palette is already tokenized as CSS variables in `app/globals.css`, which is most of the work: add a light token set under `:root[data-theme="light"]`, a toggle in the existing settings surface, and default to the OS preference. Ship it free, as promised. This is the highest-value large item for the audience most likely to want a prayer book on their phone.

**Cut the tab bar to five.** Measured hit targets at 360px: Today 35.3, Bible 31.4, Discover 50, Prayers 43, Shop 31.4, Community 67.5, You 31.4. The commerce tab and the account tab are the two narrowest, at roughly 70% of the platform minimum. A user reaching for Bible lands in the shop. Today, Prayers, Bible, Discover, You gives ~60px cells in every locale and removes the overflow class of bug entirely; Community belongs as a card on Today and Shop behind You or the existing `MobilePremiumButton` cluster, which is where Hallow and Athon put commerce. The docstring at `MobileTabBar.tsx:32` still lists six tabs and omits Community, so the set grew without anyone asking whether it still fits.

**A focus-trap hook, adopted across the 21 dialogs.** `grep -rn "focusTrap|trapFocus|inert|useFocusTrap" components/ lib/` returns zero implementations. `components/ui/Sheet.tsx:113` sets `aria-modal="true"` with no `.focus()` call and no Tab containment, and it is the primitive behind the chapter picker, reader settings and the saint-works TOC. Six dialogs move initial focus; none of the 21 restores it on close. Five have no Escape handler at all (`GiftBox`, `BibleSearchOverlay`, `OnboardingFlow`, `PrayerRope` settings, `VerseCardActions`), which is WCAG 2.1.2. One hook in `lib/ui/` next to the existing `overlay.ts` lock helpers gives Escape, initial focus, containment and restore in one adoption; `components/ui/ConfirmDialog.tsx:50-88` is the shape to lift. ## 6. What I would not do

**Do not delete `index.txt`.** It is 53.2 MB of the compressed download and it is a genuine second copy of markup already in the HTML, but removing it forces hard navigation on every in-app link: full document reload, lost scroll position, a visible flash. The pruning comments in `scripts/android-build.mjs:100-199` show this line was already considered and deliberately drawn. Land the corpus fix (2.8) and the content package fix (2.9) first; together they take assets from 170.8 MB to roughly 123 MB, and this trade may never need to be made.

**Do not flip `PLUS_ENFORCED_NATIVE` or `PLUS_ENFORCED_WEB` to fix the "nothing is gated" finding.** Four features have been free for months. Flipping the flags takes them away overnight from users who have been using them, with no migration story and no in-app explanation, and would generate more damage than the revenue it captures. Decide the ladder first, then gate at a release with copy that explains it.

**Do not rebuild `MobileCommentarySheet` on `Sheet.tsx`.** It is tempting because `Sheet.tsx` does all four things correctly, but the drag-to-dismiss gesture at lines 211-238 is unique to it and would have to be reimplemented. Likewise the two `no-img-element` warnings in `app/icon.tsx:44` and `app/apple-icon.tsx:42` are `ImageResponse` generators where `next/image` does not exist; leave them.
