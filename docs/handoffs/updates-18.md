## The mechanism (proved again this round)

A page switch is a View Transition. react-dom runs the commit's mutations and layout effects inside the transition's `update` callback (`startViewTransition` in `node_modules/next/dist/compiled/react-dom/cjs/react-dom-client.production.js`: `mutationCallback()`, then `layoutCallback()`), so **a DOM change made directly in a layout effect is in the new page's picture**. A state set in a layout effect, a passive effect, a ResizeObserver or a fetch renders only after `ready`, in the live page, and moves what is under it. Two mends work: know it in the render on the device (`useSyncExternalStore(noSubscribe, () => true, () => false)` as an "on the device" flag, then read storage or the session in the render), or write the measured result straight onto the DOM in the layout effect (a `data-` attribute the classes read), never through state.
