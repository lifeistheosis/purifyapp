  server components under `output: "export"`, so an APK showed its build day

  midnight, re-syncs on foreground) across Today, Discover, Prayers,

## 8. A guard worth knowing about

`lib/calendar/__tests__/noFrozenDay.test.ts` reads the source of
`components/{today,mobile,prayers}` and fails on any file that resolves
`new Date()` outside a client component. The frozen-day bug shipped twice, and
no type can express the rule. If it fires, do not delete the assertion: move
the computation into a client child on `useToday()`.

Known and deliberately not covered: `app/(app)/discover/page.tsx:48` and
`app/(app)/prayers/page.tsx:65` still compute the day server-side. They are
correct on the web (SSR per request) but ship into the Android export behind
`hidden md:*`, so an Android **tablet** at md+ width renders them frozen. Left
for Release B.
